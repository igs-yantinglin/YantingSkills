# 一頁式好截圖 HTML

## 問題

使用者的瀏覽器螢幕是 1920x1080,但 100% 縮放下**實際可視範圍只有約 1912x914**
(其餘被視窗邊框、分頁列、網址列吃掉)。如果直接用 1080 當版面高度上限來設計
「不用滑動」的單頁報告,內容會被切掉一截,使用者截圖時才會發現。

這條規則很容易在寫 HTML 當下被忽略——因為版面設計時想的是「內容排版好不好看」,
不會自然聯想到「瀏覽器視窗實際可視高度」這件事,即使已經知道這個限制,也常常要
等使用者提醒才想起來對照。**看到符合觸發詞的任務，要在動手寫版面前就先套用這裡的做法**，
不要等內容寫完了才回頭檢查高度。

## 做法

版面固定 **寬度** 1920px,**高度不要寫死**,讓內容自然撐開,再用 JS 量出實際高度
去算縮放比例,任何視窗大小都能完整顯示、也不會被切:

```html
<body>
<div class="page" style="width:1920px;transform-origin:top center;">
  ...版面內容...
</div>
<script>
  const pageEl = document.querySelector('.page');
  const naturalHeight = pageEl.scrollHeight; // 在套用 zoom 之前量出真實高度
  const fit = () => {
    pageEl.style.zoom =
      Math.min(1, window.innerWidth / 1920, window.innerHeight / naturalHeight);
  };
  fit();
  addEventListener('resize', fit);
</script>
</body>
```

`body` 本身不要設固定高度,用 `display:flex;justify-content:center` 讓 `.page`
置中就好。

## 踩過的雷

- **不要把 `.page` 的高度也寫死成 `1080px`**：一旦這樣做,縮放比例的分母就固定成
  1080,後續調整字級、加減內容導致實際內容高度超過 1080(例如放大字級後量到
  1249px),縮放比例還是照 1080 算,算出的 zoom 不夠小,內容照樣被切或跑版——而且
  症狀不會馬上發現,要等改了字級/加了一段才出現。用上面 `scrollHeight` 現場量測、
  不要假設固定 1080,才不會每次調內容就要重新兜一次比例。
- `body { height: 1080px; overflow: hidden }` 這種寫法,一旦內容超出可視範圍就
  **既看不到也捲不動**,使用者只會回報「網頁滑不動」,看不出是高度算錯。固定高度
  容器不要疊加 `overflow: hidden`,靠 zoom 縮放去保證永遠塞得下,而不是用裁切去藏。

## 安全預算

做版面前如果沒空跑實測,直接以 **1900x900** 當設計上限,比 1912x914 再留一點餘裕。

## 視覺風格

- **背景不要用接近純黑的深色**(例如 `#0d1117` 這種 GitHub dark 配色)。這類頁面是
  給人截圖後直接看內容用的,不是長時間盯著的 code editor,背景過暗會讓人第一眼覺得
  刺眼、不好辨識。改用中性偏深灰,或乾脆用淺色底,依報告調性挑一種即可,不要預設
  套用 code-editor 主題。
  深色主題預設色票(取自 `dataviz` skill `references/palette.md` 的 Chart chrome
  & ink,dark 欄,已驗證過對比度,比 GitHub dark 柔和):

  | 角色 | Hex |
  |---|---|
  | 畫布底(page) | `#0d0d0d` |
  | 面板(panel/card,主背景用這階) | `#1a1a19` |
  | 主文字 | `#ffffff` |
  | 次要文字 | `#c3c2b7` |
  | 輔助/次要資訊 | `#898781` |
  | 邊框 | `#2c2c2a` / `rgba(255,255,255,.10)` |
  | 強調藍 | `#3987e5` |
  | 成功綠 | `#0ca30c` |
  | 錯誤紅 | `#e66767` |

  程式碼片段語法上色,從同一份 palette 的 categorical 色階(dark 欄)裡取,不要另外
  發明一組:

  | 語法角色 | Hex | 取自 |
  |---|---|---|
  | keyword | `#e87ba4` | 磁紅 (slot 5) |
  | 型別 | `#9085e9` | 紫羅蘭 (slot 7) |
  | 字串 | `#86b6ef` | 藍色序列淺階 (sequential step 250) |
  | 數字/常數 | `#3987e5` | 藍 (slot 1,同強調色) |
  | 註解 | `#898781` | 同輔助文字 |
- **內文字級不要小於 14px**,程式碼片段字級不要小於 13px。這類頁面的目的是讓人一眼
  看懂重點,不是塞盡量多內容,字級太小會讓截圖後在聊天視窗、簡報裡顯示時更難讀。
- 跟 [[form-ux]] 共通的原則也適用在這裡:
  - **靠設計本身傳達重點,不要用小字說明句補洞**——如果一段內容需要額外一句小字
    解釋才看得懂,優先改排版、階層、分組讓它自明,不要塞 `11px` 灰字。
  - **真的要加輔助文字,就用正常字級**,不要用縮小字級當折衷。
  - **語意色(紅/綠/黃)只用在真的代表那個語意的地方**(例如錯誤、確認、警示),
    不要拿來當裝飾用的強調色。
