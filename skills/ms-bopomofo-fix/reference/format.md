# 微軟注音使用者資料格式筆記

逆向自 Windows 11 24H2（build 26100）。資料夾：`%APPDATA%\Microsoft\IME\15.0\IMETC\`

| 檔案 | 內容 |
|---|---|
| `TCHFTL.DAT` | 長期學習詞（被選 2 次以上才進來）。本工具只改這個 |
| `TCHFTS.DAT` | 最近打過的單字，每筆 12 bytes：字 u32、注音碼 u32、旗標 u32 |
| `TCLRN.IMD` | 檔頭 `USERLERN`，學習相關，未解 |
| `TCEUDP.UPT` | 使用者自建詞，檔頭 `USERDEFP`，0x1c 是筆數。紀錄從 0x80 開始，每筆開頭 u16 是這筆的長度，後面是每個字的注音碼（u16 + 補 0），再來是 UTF-16 文字 |
| `TCHFTSCJ.DAT` | 倉頡用 |

注意：檔頭 `USER` 用 UTF-16 讀出來會變成「单剅」，那不是詞。

## TCHFTL.DAT

檔頭 0x40 bytes（little-endian）：

| offset | 內容 |
|---|---|
| 0x00 | magic `13 10 10 20 4C 54 65 4D` |
| 0x08 | 檔案大小（426432） |
| 0x0c | 筆數 |
| 0x10 | 每筆大小 0x44 |
| 0x14 | 檔頭大小 0x40 |
| 0x18 | 紀錄區結尾 0x44040，所以容量是 4096 筆 |
| 0x1c | 後段區大小 0x24180 |
| 0x20 | 修改次數，每次存檔 +1 |
| 0x28 | 最後修改時間（unix time） |

每筆 0x44 bytes：

| offset | 內容 |
|---|---|
| 0x00 | 文字，UTF-16，20 bytes，不足補 0（最多 9 字） |
| 0x14 | 注音碼個數 u32（= 字數） |
| 0x18 | 注音碼 9 × u32 |
| 0x3c | 字數 u32 |
| 0x40 | 被選次數 u32（最少 2） |

- 後段區（0x44040 起）是注音音節表。實測它不隨紀錄順序或刪除改變。
- 官方工具存檔時會重新排列紀錄順序（同一個首字的詞會排在一起）。本工具的刪除只保留原順序、往前補位（輸入法讀取正常與否：待實測）。
- 實測：用官方造詞工具刪除一筆，跟本工具的刪除結果比對，紀錄內容完全一樣、後段區一樣，檔頭只差 0x28 的時間。

## 注音碼（每個字 16 bits）

`聲母 << 11 | 介音 << 9 | 韻母 << 5 | 聲調 << 2`

- 聲母：ㄅㄆㄇㄈㄉㄊㄋㄌㄍㄎㄏㄐㄑㄒㄓㄔㄕㄖㄗㄘㄙ = 1..21
- 介音：ㄧㄨㄩ = 1..3
- 韻母：ㄚㄛㄜㄝㄞㄟㄠㄡㄢㄣㄤㄥㄦ = 1..13
- 聲調：一聲 = 1、ˊ = 2、ˇ = 3、ˋ = 4、˙ = 5

例：是 ㄕˋ = `17<<11 | 4<<2 = 0x8810`

## 官方工具

`%SystemRoot%\System32\IME\shared\IMCCPHR.exe /TC /PHRUI`：微軟注音使用者造詞工具。
- 「使用者造詞」分頁對應 `TCEUDP.UPT`，「常用新詞」分頁對應 `TCHFTL.DAT`。
- 只顯示前 2500 筆。
- 「匯出常用新詞」會輸出 UTF-16 LE 文字檔，每行是「詞 + 兩個空格 + 注音」，每個音節補滿 4 格（空的部分用全形空白），一聲標成 ˉ。
- 刪除要存檔或關閉視窗才會寫入。

## 執行環境

- 輸入法引擎在 `ctfmon.exe` 裡（高權限），不是在各個應用程式裡：`tasklist /m IMTCTIP.dll` 找不到任何程式載入它。
- ctfmon 啟動時讀一次檔案，之後用記憶體資料，不會因為檔案被改而重新讀取。
- 一般權限的 `taskkill` 會被拒絕存取。
